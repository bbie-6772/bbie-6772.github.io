# bbie 문체와 생각을 보존하는 기준

## 사용자에게 직접 확인한 선호 — 2026-09-08

- “기술 설명은 정돈하되, 내 혼잣말·삽질·감정은 살리기”
- “이유를 나에게 물어 확인한 뒤, 이해에 도달하는 흐름으로 재구성”

사용자가 직접 제공한 문체 샘플:

> 내가 생각했던 건 ~~이였는데.. 설명을 다시듣고 직접 돌려보면서 검증을 해보니 느낌이 전혀달랐다..! 이제와서 생각해보면 조금 뻘짓처럼 느껴질 수 있겠지만, 나름대로 뿌듯한 접근과정이여서 좋았다

이 샘플은 예상과 실제의 차이, 직접 검증한 과정, 가벼운 자조와 뿌듯함이 함께 남아야 한다는 기준이다. 모든 글에서 같은 문구나 감정 곡선을 재사용하라는 뜻이 아니다. `~~`는 구체적인 예상이 생략된 자리이므로 기술 내용을 추측해서 채우지 않는다.

## 이 선호를 문장으로 적용하기

기술 용어와 인과관계는 명료하게 설명한다. 개인 경험 부분에는 저자가 실제 표현한 호흡과 감정을 남긴다. 문장 전체를 매끈한 교과서체로 바꾸지 않는다.

아래는 의미를 보존하며 띄어쓰기와 호흡만 정돈한 편집 예시다. 사용자가 이 완성 문구까지 승인했다는 의미는 아니다.

> 내가 생각했던 건 [처음 예상]이었는데.. 설명을 다시 듣고 직접 돌려보며 검증하니 느낌이 전혀 달랐다..!
>
> 이제 와서 보면 조금 뻘짓처럼 느껴질 수 있겠지만, 나름대로 뿌듯한 접근 과정이어서 좋았다.

실제 글에 넣기 전에는 처음 예상, 실행 방법, 달랐던 관찰과 그 이유를 질문해 채운다. 플레이스홀더는 예시에만 있으며 완성 글에 남기지 않는다.

피해야 할 편집:

- “검증을 통해 올바른 이해를 얻었다. 시행착오는 성장의 밑거름이다.”처럼 구체적인 접근과 복합적인 감정을 지우는 교훈형 요약.
- 사용자가 말하지 않은 에러·실험·결과를 만들어 완벽한 문제 해결 서사로 구성하는 것.
- 뿌듯함을 “시간 낭비였다”로 바꾸거나, 가벼운 자조를 심한 자기비하로 키우는 것.
- 모든 문단에 `..!`, `ㅋㅋ`, `뻘짓`을 덧붙여 말투를 흉내 내는 것.

## 보존할 것과 확인할 것

- 기본 설명은 자연스러운 `~다`체를 중심으로 하되, 감탄·괄호 보충·말줄임·의도적인 존댓말 전환을 문맥에 맞게 살린다.
- 맞춤법 오류 자체가 저자의 개성은 아니다. `이였는데` 등의 표기는 교정하되 감정과 문장 리듬을 함께 없애지 않는다.
- “느낌이 달랐다”는 말만으로 성능이 좋아졌다거나 버그가 해결됐다고 쓰지 않는다. 관찰한 변화의 종류를 확인한다.
- 직접 실행·측정했다는 사실과 결과는 제공된 자료 또는 답변의 범위 안에서만 쓴다.
- 저자가 “그런 이유였구나”라고 이해했는지와 편집자가 이유를 알아낸 것은 다르다. 재구성에 필요한 이해 과정은 저자에게 확인한다.
- 기존 프로젝트·경력을 끌어올 때는 이 글과 실제 연결이 있는지 먼저 본다. 연결이 있으면 쓰고, 비유가 필요해서 경력을 뒤지는 순서가 되면 그만둔다. 과거 프로필을 현재 진로·상태로 단정하지 않는다.
- 자신의 시행착오를 뿌듯해할 수 있다. 결과가 최선이 아니었다는 이유로 접근 과정의 가치를 삭제하지 않는다.
