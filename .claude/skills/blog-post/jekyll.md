# Jekyll 파일 작성과 검증

파일명, front matter 필수 키, 카테고리·태그 표기, 검사 실행 명령은 저장소 루트의 `AGENTS.md`에 있다. 여기에는 판단이 필요한 것만 적는다. 실제 작업에서는 `_config.yml`과 인접 포스트, 설치된 도구를 확인한다.

## 시리즈와 자산

- 제목은 `시리즈 - < 내용 >` 형식으로 쓴다( 예: `SSAFY - < 선형회귀 >`, `Algorithm - < 동적 계획법 >` ). `SSAFY - < 43 >`처럼 번호만 있는 제목은 쓰지 않는다. 목록과 이전·다음 링크에는 제목만 보여서, 번호로는 글 내용을 알 수 없다. 순서는 날짜와 이전·다음 링크가 대신한다. 2026-07 이전 글의 번호 제목은 고치지 않고 둔다( 2026-10-18 확인 ).
- 카테고리·태그와 시리즈 이름은 인접 글과 맞춘다. 새 글 날짜는 사용자의 요청 또는 현지 날짜를 기준으로 한다.
- 배너는 시리즈에서 실제 사용 중인 것을 재사용한다. 공통 배너 교체 요청이면 기존 자산을 보존하고 버전을 추가하며, 요청 범위의 참조를 함께 갱신한다.
- 실물 이미지는 제공된 자산 또는 URL을 사용한다.
- 큰 PNG는 webp로 바꿔 넣는다. 이 환경에는 PIL이 없고 ffmpeg가 있다: `ffmpeg -i in.png -vf "scale='min(1600,iw)':-2" -quality 82 out.webp`. 변환한 뒤 한 장은 열어서 글자가 읽히는지 본다.
- 시리즈 제목과 카테고리에는 게임·프로젝트의 정식 명칭을 쓴다. 쓰는 기술이나 모델 이름(예: Jev)은 쓰지 않는다( 2026-10-11 확인 ).

## 카테고리는 URL이다

`_config.yml`에 `permalink`가 없어서 Jekyll 기본값 `/:categories/:year/:month/:day/:title`을 쓴다. 카테고리 표기를 바꾸면 게시된 글의 주소가 바뀐다. `post_url` 내부 링크는 빌드할 때 새 주소를 따라가지만, 외부에 공유한 링크와 경로 기반 댓글 연결은 끊긴다. 바꾸기 전에 이 점을 알리고 확인받는다. 기존 주소를 지키려면 front matter에 `permalink: /<옛 카테고리 소문자>/YYYY/MM/DD/<slug>.html`을 고정한다( Algorithm으로 옮긴 글들이 이렇게 되어 있다 ). 블로그 안의 다른 글로 연결할 때는 `https://bbie-6772.github.io/...` 같은 전체 주소를 쓰지 않고 `{% post_url YYYY-MM-DD-slug %}`를 쓴다. 전체 주소는 카테고리가 바뀌어도 따라 바뀌지 않는다. OpenAI Game Builders 글의 '지난 글' 링크 6개가 `/openai_game_builders/` 주소로 남아 이렇게 깨졌었다( 2026-10-18 확인 ). 파일명과 자산 폴더는 독자에게 보이지 않으니 그대로 둔다.

## Liquid·수식

Jekyll은 코드블록 안에서도 Liquid를 처리한다. 코드 예제에서 `{{ ... }}`나 `{% ... %}` 자체를 보여주려면 그 예제를 `{% raw %}`와 `{% endraw %}`로 감싼다. 코드블록만 추가해 해결됐다고 보고하지 않는다.

`{% post_url ... %}`, `{% link ... %}`처럼 의도한 태그는 그대로 유지하고 대상 파일을 확인한다. 문법에 중괄호가 있다는 이유만으로 삭제하지 않는다. 실제 Liquid 설정도 확인한다.

수식은 현재 Markdown/MathJax 설정에 따라 렌더링을 확인한다. 이 블로그에서는 별도 줄의 `$$` 블록과 앞뒤 빈 줄이 유용하다. 과거 `\{`, `\}`, `\%`, `\` 관련 문제가 있었지만 모든 백슬래시를 무조건 바꾸지 않는다. 렌더링이 깨진 경우 `\lbrace`, `\rbrace`, 수식 블록 분리 등을 검토한다.

참고: [Jekyll 공식 Liquid 태그 문서](https://jekyllrb.com/docs/liquid/tags/).

## 필요한 경우의 개념도

그림 수를 채우기 위해 생성하지 않는다. 실제 화면·로그와 개념 그림을 구분한다. 기존 시리즈 디자인이 있으면 따른다. 기존 밝은 SVG 스타일을 재사용할 경우:

- `viewBox="0 0 720 360"` 등 내용에 맞는 높이, `width="100%"`.
- `Pretendard, -apple-system, Segoe UI, Roboto, sans-serif`.
- 배경 `#f7f9fb`, 흰 카드, 테두리 `#d5dde6`, 글자 `#1d3a5c`와 `#6b7f95`.
- 강조 `#3d6fa8`, `#8fb0d4`, 대비 `#a04040`.

한 그림에 한 가지 관계를 설명한다. XML 파싱과 실제 화면에서 글자 잘림·가독성을 확인한다. 좌표 검사만으로 시각 검증을 완료했다고 쓰지 않는다. SSAFY 교육 자료는 원본을 그대로 게시하지 않는 기존 관례를 지키고, 개념을 재구성한 경우 밝힌다.

## 검사 결과 읽기

이 검사는 얕은 YAML/Markdown 검사이며 완전한 파서나 Jekyll 빌드를 대체하지 않는다. 표 안의 파이프·백슬래시·인라인 코드는 오탐할 수 있으므로 원문과 렌더링으로 확인한다. 줄 수·이미지 장수·요약 개수·고정 소제목을 만족시키기 위한 편집은 하지 않는다.

Ruby/Bundler가 사용 가능한지 확인하고 프로젝트의 빌드 절차를 따른다. 실행 환경이 없으면 간이 검사 범위와 빌드 미실행을 보고한다. 저장소나 실행 도구가 없으면 제공된 Markdown과 자료로 작업하고 검사 미실행 사실을 알린다. 존재하지 않는 파일 접근이나 실행 결과를 주장하지 않는다.
