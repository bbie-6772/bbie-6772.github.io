# 예시: 원하는 추출 결과

## 예시 1 — 교재 학습과 실행 확인

### 원본 대화의 흐름

- "Python 책 3장을 읽었다."
- 책을 어디서 구했는지에 대한 긴 설명
- AI가 처음에 문자열과 숫자 사이의 암묵적 형변환이 항상 일어난다고 설명함
- 학습자가 직접 실행해 보고 예외가 발생함
- 학습자가 실제 규칙을 정리함
- 이틀 뒤 같은 Python 주제로 대화가 이어짐
- AI가 작업을 이틀로 나눈 회고를 쓰고, 책에 오류가 있었다고 적음

### 원하는 블로그 context

```markdown
# 학습 Context

## 주제
- Python의 형변환과 암묵적 형변환

## 핵심 개념
- 일부 연산은 피연산자 타입에 따라 암묵적 변환이 일어나지만, 문자열과 숫자의 연산처럼 허용되지 않는 조합은 자동으로 변환되지 않는다.

## 헷갈리기 쉬운 지점
- 문자열과 숫자를 더하면 한쪽으로 자동 변환될 것처럼 보이지만, Python은 이 조합을 변환하지 않고 예외를 낸다.

## 문제·실험·검증
- 문제: 문자열과 숫자 조합에서 기대한 자동 변환이 일어나지 않음
- 시도: 실제 Python 코드를 실행해 동작을 확인함
- 결과: 예외가 발생함

## 재사용할 지식
- 언어의 타입 변환 규칙을 일반화해서 가정하지 말고, 연산자·피연산자 조합별 규칙을 확인한다.

## 남은 확인 사항
- 다른 연산자와 타입 조합의 암묵적 변환 규칙은 별도 확인 필요
```

### 일부러 지운 것

- 교재 제목과 읽은 과정
- AI의 잘못된 설명을 사건으로 쓴 서사
- 지어낸 "1일차 / 2일차" 구분
- 독립 검증 없이 "교재가 틀렸다"고 한 주장
- 일반적인 동기 부여 문구

"실행해 확인함"은 학습자가 직접 한 일(L)이고 실행이라는 행위 자체가 정보라서 행동 문장으로 남겼다. 기술적 교정은 관찰된 테스트와 직접 연결되고 독자도 같은 오해를 할 만하므로 「헷갈리기 쉬운 지점」에 개념 대비로 남겼다.

## 예시 2 — 소크라테스식 문답 세션

### 원본 대화의 흐름

- AI: "Kruskal에서 두 정점의 대표자가 같으면 왜 사이클인가?"
  - 학습자: "같은 집합 안에서 새로운 연결을 만들기 때문" → AI: 결론은 맞지만 "같은 집합"의 의미가 빠졌다고 판정
  - 학습자: "같은 집합이면 두 정점 사이에 간선이 있다" → AI가 (a, b), (b, c) 반례 제시
  - 학습자: "이미 선택한 간선들로만 이루어진 경로가 있다" → AI: 통과
- AI: "최적화 없는 Kruskal의 `find_set` 총비용은?"
  - 학습자: "1,000" → AI: 한 번의 비용이니 호출 횟수 2E를 곱하라며 곱셈식 제시
  - 학습자: "20억 / 10⁷ = 200초, 어림도 없음"
- AI: "Prim은 음수 가중치를 처리할 수 없다는 슬라이드 서술이 맞는가?"
  - 학습자: "솔직히 잘 모르겠는데?"
  - AI가 작은 그래프로 손 추적과 신장 트리 전수 나열을 해 보임
- AI: "던전 복도 총길이를 최소로 하려면 MST와 최단 경로 트리 중 무엇인가?"
  - 학습자: "다익스트라 같다" → AI: 반대라고 판정, 빈칸 표 제시
  - 학습자가 표를 채움. 한 문장 정리는 비워 둠 → AI가 정리 문장을 대신 씀
- 학습자: "벽돌 깨기에서 어디서 무한루프가 생길까?"
  - AI가 중력 루프를 지목하고 원인 설명
  - 학습자가 수정한 코드를 올림

### 원하는 블로그 context

```markdown
# 학습 Context

## 주제
- 서로소 집합과 최소 신장 트리, 벽돌 깨기 디버깅

## 핵심 개념
- Kruskal에서 같은 집합의 두 정점 사이에는 이미 선택한 간선들로만 이루어진 경로가 있다. 그래서 그 사이에 간선을 더하면 사이클이 된다.
- 최적화 없는 서로소 집합으로 Kruskal을 돌리면 `find_set`이 2E번 호출되고 한 번에 O(V)다. V = 1,000, E = 1,000,000이면 약 20억 번이고, Python 어림 기준 약 200초라 제한 2초를 크게 넘는다.
- A−B(−5), A−C(2), B−C(3) 그래프에서 Prim 결과와 전수 최솟값은 모두 −3이다. Prim은 간선끼리 대소 비교만 하므로 음수 가중치에서도 동작한다.

## 헷갈리기 쉬운 지점
- 같은 집합이라고 두 정점 사이에 간선이 있는 것은 아니다. 있는 것은 선택한 간선들로 이어진 경로다.
- 복도 총길이 최소화는 최단 경로 트리처럼 보이지만, 최단 경로 트리가 줄이는 것은 시작점에서 각 정점까지의 거리다. 간선 가중치 합을 줄이는 것은 MST다.

## 문제·실험·검증
- 문제: 벽돌 깨기 중력 처리에서 무한루프
- 원인: 빈칸에 빈칸을 끌어오면 값이 계속 0이라 `while not cur_board[i][j]`의 탈출 조건이 진행되지 않는다
- 수정 (학습자 코드): 열마다 아래에서 위로 훑고, 빈칸이면 위쪽에서 가장 가까운 벽돌을 끌어온다

## 재사용할 지식
- 무한루프는 반복문마다 "한 바퀴 돌 때 탈출 조건 쪽으로 반드시 진행하는가"로 점검한다.

## 학습자가 직접 한 말
- "20억 / 10⁷ = 200초, 어림도 없음" — 최적화 없는 Kruskal의 예상 시간

## 근거 상태
- UNVERIFIED: Python 초당 10⁷회 어림값
```

### 일부러 지운 것

- "1,000이라고 답했다가 고쳤다": 곱할 항을 빠뜨린 계산 실수다. 최종 계산만 남긴다.
- "처음엔 결론만 맞고 이유가 빠졌다": 결론은 맞고 근거가 불완전했던 답이다.
- "이미 선택한 간선들로 이루어진 경로가 있다고 답했다": 학습자가 맞힌 개념 답(L)이지만 답했다는 행위는 정보가 아니다. 「핵심 개념」에 지식 문장으로만 남긴다.
- "Prim 음수 서술을 판단하지 못했다": 무응답은 오해가 아니다.
- "작은 그래프로 확인했다", "손으로 따라가 보니": 손 추적은 AI가 했다(A). 지식 문장으로만 남긴다.
- "표를 직접 채워 이해가 바뀌었다": 표의 틀은 AI가, 정리 문장도 AI가 썼다. 결과 지식만 남긴다.
- "통과", "오답", "반대입니다" 같은 AI 판정어
- "무한루프를 제일 오래 붙잡았다": 대화에 그런 발언이 없다. 학습자는 바로 AI에게 위치를 물었다.
- 무한루프 원인을 "찾았다"는 행동 문장: 원인은 AI가 짚었다. 원인은 지식 문장으로, 수정만 학습자 코드로 기록한다.

「헷갈리기 쉬운 지점」의 두 항목은 예외 조건을 모두 통과한 것이다. 둘 다 개념이 동작하는 방식에 대한 오해이고, 고치면 개념의 이해가 달라지며, 독자도 같은 오해를 할 만하다. 오답 이력이 아니라 개념 대비로 썼다.

「학습자가 직접 한 말」에는 학습자가 스스로 덧붙인 반응 하나를 고치지 않고 옮겼다. "솔직히 잘 모르겠는데?"는 AI 질문에 대한 무응답이라 넣지 않았다. 학습자가 기억에 남는다고 말한 장면은 대화에 없어서 만들지 않았고, 파일을 전달한 뒤 한 번 묻는다.
