# 근거와 환각 방지 규칙

## 근거 위계

학습자 자신의 작업에 대한 주장:

1. 학습자의 명시적 발언
2. context에 있는 도구·파일 출력의 직접 관찰
3. 명시적으로 인용된 출처 자료
4. 합리적 추론

외부 기술 사실에 대한 주장:

1. 공식·1차 문서
2. 버전이 명시된 신뢰할 만한 2차 문서
3. 기타 2차 근거
4. 주장이 안정적이고 최신 검증이 필요 없을 때만 모델 지식

그럴듯하게 들린다는 이유로 낮은 신뢰도의 출처를 격상하지 않는다.

## 사용자 결정과 AI 제안

AI의 제안은 학습자가 그 방법을 받아들이거나, 선택하거나, 구현하거나, 자신의 행동으로 보고했다고 대화에서 드러날 때만 사용자 결정으로 기록한다.

예시:

- AI: "오브젝트 풀을 써보세요."
- 사용자: "좋아, 오브젝트 풀을 적용했어."

구현은 사용자의 행동으로 기록한다. 사용자가 명시적으로 말하지 않았다면, AI의 제안 이유를 사용자의 원래 이유로 적지 않는다.

## 귀속 판정

근거 상태(FACT 등)는 내용이 참인지를 판정하고, 귀속은 누가 만들었는지를 판정한다. 두 축은 독립적이다.

| 대화에서 일어난 일 | 귀속 | 기록 방식 |
|---|---|---|
| 학습자가 코드를 실행·측정·구현·수정함 | L | 행동 문장 허용 |
| 학습자가 개념 질문에 스스로 맞힘 | L | 지식 문장으로 기록. 행위가 정보가 아니므로 행동 문장은 쓰지 않음 |
| AI가 빈칸 표·식을 주고 학습자가 채움 | L+S | 결과만 기록. "유도했다" 금지 |
| AI가 반례를 만들고 손 추적함 | A | 지식 문장으로 기록 |
| 학습자가 비워 둔 답을 AI가 채움 | A | 지식 문장으로 기록 |
| AI가 "결론이 반대"라고 판정하고 학습자가 받아들임 | A | 최종 지식만 기록. "결론을 고쳤다" 금지 |
| 학습자가 "모르겠다"고 답하고 AI가 설명함 | A | 지식 문장으로 기록. 무응답 사실은 기록하지 않음 |
| 학습자가 AI에게 버그 위치를 묻고 AI가 원인을 짚음 | A (원인) / L (수정 코드) | 원인은 지식 문장, 수정은 학습자 코드로 기록 |

판단이 애매하면 A로 둔다.

### 예시

대화:

- AI: "Prim이 음수 가중치를 처리할 수 없다는 서술이 맞을까요?"
- 학습자: "솔직히 잘 모르겠는데?"
- AI: A−B(−5), A−C(2), B−C(3) 그래프로 Prim을 손 추적하고, 모든 신장 트리를 나열해 최솟값 −3이 일치함을 보임

잘못된 기록:

> 작은 그래프로 확인했다. Prim 결과와 전수 최솟값이 모두 −3이었다.

올바른 기록:

> A−B(−5), A−C(2), B−C(3) 그래프에서 Prim 결과와 전수 최솟값은 모두 −3이다. Prim은 간선끼리 대소 비교만 하므로 가중치의 부호에 영향을 받지 않는다.

## 관찰과 원인

일어난 일과 그 이유를 분리한다.

나쁜 예:

> X를 바꿔서 성능이 좋아졌다. X가 할당을 줄이기 때문이다.

나은 예:

> X를 바꾼 뒤 관찰한 테스트에서 프레임 시간이 줄었다. 메커니즘은 독립적으로 검증하지 않았다.

## 빠진 context

다음을 말없이 합치지 않는다.

- 별개 프로젝트
- 별개 학습 세션
- 별개 날짜
- 별개 버전
- 키워드만 같은 별개 문제

연속성이 불확실하면 단위를 분리해 두거나, 연속성이 확인되지 않았다고 적는다.

## 최신 사실

버전에 민감한 주장은 다음과 같다.

- 패키지·API 동작
- 엔진·에디터 동작
- 언어·런타임 릴리스
- 클라우드 서비스 제한
- 플랫폼 지원
- 라이선스·사용 규칙
- 현재 제품 기능

이 주장들이 context에 실질적인 영향을 주고 적절한 출처가 있으면 검증한다.
