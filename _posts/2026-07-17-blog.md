#### 악마의 탄생

그렇게 실행을 했음에도 변화가 없자, 깃허브 액션 쪽의 워크플로우를 최신 Jekyll 툴로 변경해주었다! 그러자..

![polyfill](https://github.com/user-attachments/assets/593ca315-5844-4519-bd56-3db82a1aa515)

??? 이상한 놈이 사이트 접속간 계속 뜨게 된다.. 이후 AI + 서칭을 진행하였다.

- poilyfill.io는 구형 웹브라우저에 최신 기술 호환성을 위한 오픈소스 였으나, 외부 스크립트 변조로 악성코드를 유포하는 공급망 공격이 발생했다고한다.

- 저 창에 로그인을 입력하는 것은.. 절대 하지 않는걸 추천한다..

이제 이놈을 어떻게 처리해야하는가에 대해 논의를 많이하고 시행착오를 겪었지만.. 정작 소스코드내에는 polyfill.io 에 관한 코드가 없다고 떳다.

> 소스 코드에 없다면 배포 코드를 확인하자 

깃헙 액션에 나오는 Artifacts 란을 확인해 다운로드 후 확인해보았다.

![과정](https://github.com/user-attachments/assets/1e092529-f1a9-4f29-83f1-f50a5e9f9283)

그 후 확인해보니 _index.html 에 아래와 같은 코드가 숨겨져 있었다.

![악마발견](https://github.com/user-attachments/assets/4d05a6fa-e03e-427f-a6c9-ca1e4751f68e)

복잡한 수학 수식을 예쁘고 선명하게 보여주는 라이브러리인 MathJax(최신)와 polyfill.io(구식용)을 같이 가져오는 과정에서 악성코드가 딸려 들어오는 것이었다..

```_cofing.yml
# polyfill.io 악성코드 주입 방지
jekyll-spaceship:
  mathjax-processor:
    src:
      - https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js
```
그렇기에 polyfill.io를 제외한 안전한 mathjax만 가져오도록 하여 악마를 퇴마했다.  
( 중간 과정에서 원인을 몰라 쓸데없이 여러 파일을 수정한 커밋들이 있으나 생략하겠다. )

#### 다시 시작

이제 생겨난 문제를 해결하였고, 페이징 기법이 왜 안돼는지 다시한번 확인을 하기 시작했다

1. 페이지 길잡이 : 컴퓨터가 페이지를 쪼갠 뒤, 어떤 주소로 만들어줄지 지정을하지 않음

2. _config.yml 에서 1탭이 들어간 상태로 작성되어 테마 "yat:" 내부 속성으로 잘못 인식 되었음.

위의 문제들을 확인하고 원하는 페이지 수를 맞추어 수정하였다

```yml
paginate: 8
paginate_path: "/page:num/"
```

이후 작동은 잘됬으나, 시크릿 탭에서 접속 시 로딩시간이 너무 긴 현상이 발생하여(원래부터 그랬지만) 해결방안을 나중에 확인해보려 한다
