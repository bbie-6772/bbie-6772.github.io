## IOCP(Input/Ouptput Completion Port)

- Windows NT 버전 3.5 이상, AIX 및 Solaris 10 이상의 운영 체제 에서 지원하는 기능

- 소켓이나 파일의 입출력을 최소한의 스레드를 사용해서 처리하는 기법

- 커널이 요청한 Overlapped(비동기) 작업의 완료를 실시간으로 알려주는 대신,  
작업 결과를 IOCP 큐에 넣고 나중에 사용자가 지정한 방법으로 통지하는 방식

- 여러 파일 핸들의 동기화 지점을 단일 개체로 결합하는 것

- IOCP는 스레드 풀링(Thread Pooling) + 논 블로킹(Non-Blocking) + 중첩 입출력(Overlapped I/O)과 같은 개념들을 이용해서 작동

### 사용 이유

- 작업을 스레드에 분산하여 최신 멀티프로세서 호스트를 활용해야 함
( 멀티프로세서 호스트는 한 컴퓨터 시스템 내에서 두 개 이상의 CPU가 장착되어 가능한 멀티 프로세싱 환경을 지칭 )

- I/O 작업 처리가 응답성과 처리량을 극대화하기 위해 효과적으로 예약되어야 함

### 기능 

여러 개의 동시 비동기 입출력 작업을 수행하기 위한 API

입출력 완료 포트 개체가 생성되어 여러 소켓 이나 파일 핸들 과 연결

I/O 서비스가 요청되면 I/O 완료 포트에 대기된 메시지 로 완료가 표시됩니다 .

I/O 서비스를 요청하는 프로세스는 I/O 서비스 완료 알림을 받지 않고 대신 I/O 완료 포트의 메시지 대기열을 확인하여 I/O 요청 상태를 확인

I/O 완료 포트는 여러 스레드 와 해당 동시성을 관리

IOCP의 장점

스레드 풀(Thread Pool)을 쉽게 사용할 수 있다.
(운영체제가 직접 스레드 풀링 관리)

스레드를 효율적으로 사용하므로 CPU 자원소모가 줄어든다.

Context Switching 비용이 줄어든다.

winsock2 API 중에서 확장성과 성능이 뛰어나다.

IOCP의 단점

프로그램 구현이 복잡해진다.

일부 운영 체제에서만 사용 가능

하나의 I/O operation마다 버퍼 영역에 대한 page-loock/unlock이 필요하다.
( 이를 회피하기 위한 zero-byte, zero-byte recv )

하나의 I/O operation마다 시스템 콜이 발생한다.

Windows의 Input/Output Completion Port(IOCP)

대규모 네트워크 또는 파일 I/O를 효율적으로 처리하기 위한 비동기 이벤트 알림 메커니즘

스레드 수를 최소화하면서도 높은 동시성을 제공

커널 차원에서 I/O 처리를 스케줄링하여 CPU 사용량을 최적화

대규모 서버 애플리케이션에서 성능과 확장성을 확보하기 위해 흔히 사용


#### 스레드(Thread) / Thread Pooling

스레드 는 실행을 위해 예약할 수 있는 프로세스 내의 엔티티 프로세스의 모든 스레드는 가상 주소 공간과 시스템 리소스를 공유

스레드는 예외 처리기, 스케줄링 우선 순위, 스레드 로컬 스토리지, 고유한 스레드 식별자 및 시스템이 스케줄링될 때까지 스레드 컨텍스트를 저장하는 데 사용할 구조 세트를 유지 관리

스레드 컨텍스트 에는 스레드의 머신 레지스터 세트, 커널 스택, 스레드 환경 블록 및 스레드 프로세스의 주소 공간에 있는 사용자 스택이 포함

애플리케이션은 스레드 풀을 사용하여 애플리케이션 스레드 수를 줄이고 작업자 스레드를 관리

애플리케이션은 작업 항목을 큐에 넣고, 대기 가능한 핸들과 작업을 연관시키고, 타이머에 따라 자동으로 큐에 넣고, I/O와 바인딩

- 스레드 풀

스레드 풀은 애플리케이션을 대신하여 비동기 호출을 효율적으로 실행하는 작업자 스레드의 모음

애플리케이션 스레드 수를 줄이고 작업자 스레드를 관리하는 데 사용

CPU에 무리가 가는 잦은 생성과 파괴 작업을 피하는 대신 상태만 활성화/비활성화함으로 오버헤드를 줄임

쓰레드 간 작업 전환 시의 발생하는 Context Switching에 대해서도 풀의 쓰레드를 상황에 맞춰 조절함으로 회피가능

#### 동기 및 비동기 I/O

입력/출력(I/O) 동기화에는 동기 I/O와 비동기 I/O의 두 가지 유형이 있습니다. 비동기 I/O는 중첩 I/O(Overlap I/O)라고도 합니다

동기 파일 I/O 에서 스레드는 I/O 작업을 시작하고 I/O 요청이 완료될 때까지 즉시 대기 상태에 들어갑

비동기 파일 I/O를 수행하는 스레드는 적절한 함수를 호출하여 커널에 I/O 요청을 보냅

요청이 커널에 의해 수락되면 호출 스레드는 커널이 스레드에 I/O 작업이 완료되었음을 알릴 때까지 다른 작업을 계속 처리

I/O 요청이 많은 시간이 걸릴 것으로 예상되는 상황(예: 대규모 데이터베이스의 새로 고침 또는 백업 또는 느린 통신 링크)에서 비동기 I/O는 일반적으로 처리 효율성을 최적화하는 좋은 방법

빠른 I/O 작업의 경우 커널 I/O 요청과 커널 신호를 처리하는 오버헤드로 인해 비동기 I/O가 덜 유익할 수 있으며, 특히 많은 빠른 I/O 작업을 해야 하는 경우 더욱 그렇

### 수행 과정

- 애플리케이션이 초기화될 때마다 .NET 런타임은 다음과 같이 CreateIoCompletionPort 함수를 사용하여 완료 포트 객체를 생성

- 모든 완료 포트는 여러 파일 핸들 또는 파일 설명자와 연관  
( 파일 핸들은 디스크의 파일이나 모든 네트워크 엔드포인트 또는 TCP 소켓에 대한 읽기/쓰기를 나타냄 )

- 완료 포트가 생성되면 OS는 모든 I/O 완료 요청 패킷을 유지하기 위해 대기열을 생성하고 연결하여 애플리케이션 작업자 스레드를 할당하고 이 요청을 추가로 처리할 수 있음

- I/O 요청이 완료되면 I/O 스레드는  IOCP에서 PostQueuedCompletionStatus 함수를 호출하여 완료 요청 패킷을 연관된 대기열(선입선출(FIFO))로 이동하고 사용 가능한 스레드 풀로 다시 이동

- 애플리케이션 작업자 스레드가 사용 가능해지면  GetQueuedCompletionStatus  함수를 호출하여 IOCP 대기열에서 완료 패킷을 가져오고 추가 작업을 계속 진행

## 단어장

### I/O 개념

로컬 및 원격 컴퓨터에 있는 스토리지 구성 요소에 대한 입력 및 출력(I/O) 작업을 수행하는 기능

동기 및 비동기 I/O
입력/출력(I/O) 동기화에는 동기 I/O와 비동기 I/O의 두 가지 유형이 있습니다. 비동기 I/O는 중첩 I/O라고도 합니다.

I/O 완료 포트
I/O 완료 포트는 멀티프로세서 시스템에서 여러 개의 비동기 I/O 요청을 처리하기 위한 효율적인 스레딩 모델을 제공

### 파일 핸들

- 운영체제가 특정 파일에 대한 입출력 작업을 수행할 수 있도록 제공하는 고유한 식별자

- 파일 핸들 및 파일 개체는 일반적으로 파일을 여는 각 프로세스에 고유

- 특정 파일 핸들과 관련된 I/O 작업이 완료되면 해당 핸들이 완료 포트에 의해 관리되며, 상태 블록을 통해 결과를 전달받게 됨

### 커널 (kernel)

커널은 운영체제 중 항상 메모리에 올라가 있는 운영체제의 핵심 부분으로써 하드웨어와 응용 프로그램 사이에서 인터페이스를 제공하는 역할을 하며 컴퓨터 자원들을 관리하는 역할
