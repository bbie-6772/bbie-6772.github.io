## IOCP(Input/Ouptput Completion Port)

Window에서만 사용이 가능

고성능 비동기 입력/출력 작업을 위해 사용

커널이 요청한 Overlapped 작업의 완료를 실시간으로 알려주는 대신, 작업 결과를 IOCP 큐에 넣고 나중에 사용자가 지정한 방법으로 통지하는 방식

용자로 하여금 커널의 상태를 지속적으로 확인할 필요 없이 특정 이벤트가 발생했을 때만 통지를 받을 수 있게 해줌

### 파일 관리

파일 객체는 I /O 시스템에서 관리할 수 있는 리소스(물리적 장치 또는 물리적 장치에 있는 리소스)의 표현을 제공

### I/O 개념

파일 버퍼링
파일 버퍼링, 즉 버퍼링되지 않은 파일 입출력(I/O)의 애플리케이션 제어에 대한 고려 사항을 설명합니다

파일 캐싱
Windows는 디스크에서 읽은 파일 데이터와 디스크에 쓴 파일 데이터를 캐시합니다.

동기 및 비동기 I/O
입력/출력(I/O) 동기화에는 동기 I/O와 비동기 I/O의 두 가지 유형이 있습니다. 비동기 I/O는 중첩 I/O라고도 합니다.

보류 중인 I/O 작업 취소
느리거나 차단된 I/O 요청을 사용자가 취소할 수 있도록 하면 애플리케이션의 유용성과 견고성이 향상될 수 있습니다.

경고 가능한 I/O
경고 가능 I/O는 애플리케이션 스레드가 경고 가능 상태에 있을 때만 비동기 I/O 요청을 처리하는 방법입니다.

I/O 완료 포트
I/O 완료 포트는 멀티프로세서 시스템에서 여러 개의 비동기 I/O 요청을 처리하기 위한 효율적인 스레딩 모델을 제공합니다.

#### 파일 버퍼링

버퍼링되지 않은 파일 입출력(I/O)이라고도 하는 **파일 버퍼링의 애플리케이션 제어에 대한 다양한 고려 사항**
( 버퍼링 : 임시 저장소에 저장하는 작업 )

FILE_FLAG_NO_BUFFERING 플래그를 지정하여 파일에서 읽거나 파일에 쓰는 데이터의 시스템 캐싱을 비활성화 가능

데이터 I/O 버퍼링에 대한 완전하고 직접적인 제어가 가능하지만 파일 및 이와 유사한 장치의 경우 고려해야 할 데이터 정렬 요구 사항이 있음

물리적 디스크 레이아웃, 파일 시스템 스토리지 레이아웃 및 시스템 수준 파일 포인터 위치 추적으로 인해 로컬로 정의된 데이터 버퍼가

다음 섹션에서 설명하는 특정 정렬 기준을 충족하지 않는 한, 쓰기 작업은 실패

OVERLAPPED 구조 의 선택적 파일 오프셋을 포함한 **파일 액세스 크기는 지정된 경우 볼륨 섹터 크기의 정수 배수인 바이트 수**여야 합니다. 
예를 들어, 섹터 크기가 512바이트인 경우 애플리케이션은 512, 1,024, 1,536 또는 2,048바이트의 읽기 및 쓰기를 요청할 수 있지만 335, 981 또는 7,171바이트는 요청할 수 없습니다.

읽기 및 쓰기 작업을 위한 **파일 액세스 버퍼 주소는 물리적 섹터 정렬**이어야 합니다. 
즉, 볼륨의 물리적 섹터 크기의 정수 배수인 메모리 주소에 정렬되어야 합니다. 디스크에 따라 이 요구 사항이 적용되지 않을 수 있습니다.

논리적 섹터: 미디어의 논리적 블록 주소 지정에 사용되는 단위입니다. 
스토리지가 수용할 수 있는 가장 작은 쓰기 단위로 생각할 수도 있습니다. 이것이 "에뮬레이션"입니다.

물리적 섹터: 장치에 대한 읽기 및 쓰기 작업이 단일 작업으로 완료되는 단위입니다. 
이는 원자 쓰기의 단위이며, 버퍼링되지 않은 I/O가 최적의 성능과 안정성 특성을 갖기 위해 정렬되어야 하는 단위입니다

#### 파일 캐싱

Windows는 디스크에서 읽고 디스크에 쓴 파일 데이터를 캐시합니다. 
즉, 읽기 작업은 물리적 디스크가 아닌 시스템 파일 캐시라고 하는 시스템 메모리의 영역에서 파일 데이터를 읽음

#### 동기 및 비동기 I/O

입력/출력(I/O) 동기화에는 동기 I/O와 비동기 I/O의 두 가지 유형이 있습니다. 비동기 I/O는 중첩 I/O라고도 합니다

동기 파일 I/O 에서 스레드는 I/O 작업을 시작하고 I/O 요청이 완료될 때까지 즉시 대기 상태에 들어갑

비동기 파일 I/O를 수행하는 스레드는 적절한 함수를 호출하여 커널에 I/O 요청을 보냅

요청이 커널에 의해 수락되면 호출 스레드는 커널이 스레드에 I/O 작업이 완료되었음을 알릴 때까지 다른 작업을 계속 처리

I/O 요청이 많은 시간이 걸릴 것으로 예상되는 상황(예: 대규모 데이터베이스의 새로 고침 또는 백업 또는 느린 통신 링크)에서 비동기 I/O는 일반적으로 처리 효율성을 최적화하는 좋은 방법

빠른 I/O 작업의 경우 커널 I/O 요청과 커널 신호를 처리하는 오버헤드로 인해 비동기 I/O가 덜 유익할 수 있으며, 특히 많은 빠른 I/O 작업을 해야 하는 경우 더욱 그렇

#### 보류 중인 I/O 작업 취소

I/O 작업을 발행한 프로세스의 모든 스레드에서 비동기 I/O를 취소할 수 있습니다. I/O가 수행된 핸들과 선택적으로 I/O를 수행하는 데 사용된 오버랩 구조를 지정해야 합

I/O 작업을 발행한 프로세스의 모든 스레드에서 동기 I/O를 취소할 수 있습니다. 현재 I/O 작업을 수행 중인 스레드에 대한 핸들을 지정해야 합

#### 경고 가능한 I/O

경고 가능 I/O는 애플리케이션 스레드가 경고 가능 상태에 있을 때만 비동기 I/O 요청을 처리하는 방법

### 기능

여러 개의 동시 비동기 입출력 작업을 수행하기 위한 API

입출력 완료 포트 개체가 생성되어 여러 소켓 이나 파일 핸들 과 연결

I/O 서비스가 요청되면 I/O 완료 포트에 대기된 메시지 로 완료가 표시됩니다 .

I/O 서비스를 요청하는 프로세스는 I/O 서비스 완료 알림을 받지 않고 대신 I/O 완료 포트의 메시지 대기열을 확인하여 I/O 요청 상태를 확인

I/O 완료 포트는 여러 스레드 와 해당 동시성을 관리




소켓이나 파일의 입출력을 최소한의 스레드를 사용해서 처리하는 기법

이를 위한 스레드 풀링이나 비동기 처리등을 운영체제에서 관리해주기 때문에 사용자는 IOCP를 이용해서 쉽고 빠르게 고성능의 입출력 처리가 가능

추가적으로 설명하자면, 중첩 입출력(Overlapped I/O)이 완료되면 사용자에게 이를 통지해 주는 커널 오브젝트

IOCP는 비동기(Asynchronous) + 스레드 풀링(Thread Pooling) + 논 블로킹(Non-Blocking) + 중첩 입출력(Overlapped I/O)과 같은 개념들을 이용해서 작동

IOCP의 장점

스레드 풀(Thread Pool)을 쉽게 사용할 수 있다.
(운영체제가 직접 스레드 풀링 관리)

스레드를 효율적으로 사용하므로 CPU 자원소모가 줄어든다.

Context Switching 비용이 줄어든다.

winsock2 API 중에서 확장성과 성능이 뛰어나다.

IOCP의 단점

프로그램 구현이 복잡해진다.

Window에서만 사용이 가능하다.

하나의 I/O operation마다 버퍼 영역에 대한 page-loock/unlock이 필요하다.
( 이를 회피하기 위한 zero-byte, zero-byte recv )

하나의 I/O operation마다 시스템 콜이 발생한다.



Windows의 Input/Output Completion Port(IOCP)

대규모 네트워크 또는 파일 I/O를 효율적으로 처리하기 위한 비동기 이벤트 알림 메커니즘

스레드 수를 최소화하면서도 높은 동시성을 제공

커널 차원에서 I/O 처리를 스케줄링하여 CPU 사용량을 최적화

대규모 서버 애플리케이션에서 성능과 확장성을 확보하기 위해 흔히 사용

#### 파일 핸들

파일 핸들 이라는 용어는 디스크의 파일뿐만 아니라 중첩된 I/O 엔드포인트를 나타내는 시스템 추상화  
(네트워크 엔드포인트, TCP 소켓, 명명된 파이프 또는 메일 슬롯이 될 수 있음)

#### 커널

커널은 운영체제 중 항상 메모리에 올라가 있는 운영체제의 핵심 부분으로써 하드웨어와 응용 프로그램 사이에서 인터페이스를 제공하는 역할을 하며 컴퓨터 자원들을 관리하는 역할

컴퓨터의 물리적(하드웨어) 자원과 추상화 자원을 관리 하는 것

커널은 또한 서로 다른 프로세스 간의 충돌을 방지하고 완화하는 역할



#### 스레드

스레드 는 실행을 위해 예약할 수 있는 프로세스 내의 엔티티 프로세스의 모든 스레드는 가상 주소 공간과 시스템 리소스를 공유

스레드는 예외 처리기, 스케줄링 우선 순위, 스레드 로컬 스토리지, 고유한 스레드 식별자 및 시스템이 스케줄링될 때까지 스레드 컨텍스트를 저장하는 데 사용할 구조 세트를 유지 관리합니다. 

스레드 컨텍스트 에는 스레드의 머신 레지스터 세트, 커널 스택, 스레드 환경 블록 및 스레드 프로세스의 주소 공간에 있는 사용자 스택이 포함

애플리케이션은 스레드 풀을 사용하여 애플리케이션 스레드 수를 줄이고 작업자 스레드를 관리

애플리케이션은 작업 항목을 큐에 넣고, 대기 가능한 핸들과 작업을 연관시키고, 타이머에 따라 자동으로 큐에 넣고, I/O와 바인딩

- 스레드 풀

스레드 풀은 애플리케이션을 대신하여 비동기 콜백을 효율적으로 실행하는 작업자 스레드의 모음

애플리케이션 스레드 수를 줄이고 작업자 스레드를 관리하는 데 사용
