### 현 상황

어제 대략적인 구조를 수정한 후, Claude Code에 붙여 오늘은 프로토타입을 실행해볼 예정이다.

#### 프로토타입 게임 진행

입력으로 "포스트 아포칼립스 배경의 귀염뽀짝한 동물들 게임, 전체 파이프라인" 라고 진행하며 게임 생성을 진행해보았다. (Unity MCP 를 구동하기 위해 별도의 Unity Project를 오픈 해둠 )

![게임화면](https://github.com/user-attachments/assets/3b2b6a1c-f7aa-4640-9dc4-35689e71a957)

![구조](https://github.com/user-attachments/assets/b9a4d923-61f8-4077-87bc-b08fc73d8679)

기본 적으로 아이디어를 입력하면, RAG 기술을 게임 기획에 대한 요소/장르/시장 반응 을 읽어온다. ( 유사도가 높아 시너지가 좋은 것과 반례 예시를 검색 ) 이후 이 아이디어를 토대로 spec(기능) 단위로 쪼개어 설계도를 작성한다. 설계도를 통해 Unity MCP 도구로 구현을 시작한 후 자체적인 검증 후 마무리를 하는 형식으로 진행되었다. ( 약 5만개 토큰 소모 )

- 생각보다 구현 원활하게 진행되어 추가적인 개선사항 및 토큰 사용량 최적화 방안을 생각해보려 한다.

#### 개선 사항

1. 아이디어 검토 프로세스 추가

        현재 첫 입력으로 준 아이디어를 제외하곤, 추론 및 DB 검색을 통해 추가된 아이디어 완성본에 사람이 관여를 하지 못하고 진행된다. 이에 중간에 확인을 받고 아이디어 개선을 가능하도록 프로세스를 추가하는게 필요해 보인다.

2. 에셋 생성 방식 개선

        현재 생성된 에셋들이 너무나도 제한적이다. 단순히 프로토타입 제작이라면 크게 문제는 없지만, 우리는 최소한의 기준을 만족했으면 좋겠다고 생각한다. 그렇기에 에셋 생성에 최적화된 Unity AI Assistant를 부분적 도입해보려 한다. ( 메인 파트에 ) 

3. 토큰 최적화 방안 검토

        한 번 실행에 50K 토큰이 사라지는게 결과물에 따라 다르게 생각할진 모르지만, 현재는 너무 비용이 큰 것 같기에 최적화 방안을 검토하여 하나하나 적용해볼 예정이다.

4. 프롬프트 최적화 및 오류 개선

        Unity MCP에 연결된 개발 AI의 프롬프트에서 한 파일에 퍼블릭 클래스는 1개로 제한해두는 이상한 제한조건이 있었기에, 제한 조건들을 제대로 검토해가며 최적화를 진행할 예정이다.


## 한줄 평

- 내일 부터 게임 개발에 본격적으로 들어가기에 구현과정에서 프로세스 디버깅을 계속해서 진행할 것 같다.
